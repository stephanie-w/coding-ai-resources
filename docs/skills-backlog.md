# Skills Backlog & Evaluation Catalog

A reference catalog of candidate agent skills extracted from [`cursor/plugins/pstack`](https://github.com/cursor/plugins/tree/main/pstack/skills), evaluated for Python development, Neovim/CLI workflows, and Data Science.

---

## 1. Code Cleanliness & Style Enforcement

### `unslop`
- **Source:** `pstack/skills/unslop`
- **Summary:** Eliminates hallmark AI writing tells from documentation, commit messages, and summaries.
- **Rules:** Strips puffery (*pivotal, landscape, tapestry, enhance, delve, crucial*), false ranges, superficial `-ing` phrases, and excessive punctuation (em dashes, mid-sentence colons).
- **Target Stack:** Universal (Python docstrings, technical documentation, PR notes).

### `no-comments`
- **Source:** `pstack/skills/no-comments`
- **Summary:** Strips obvious, redundant, or decorative comments generated by LLMs before committing code.
- **Rules:** Removes line-by-line restatements (e.g. `# Initialize list`, `# Loop through items`). Enforces that Python code explains *why* in docstrings rather than *what* in clutter comments.
- **Target Stack:** Clean Python buffers, Neovim editing.

### `technical-writing`
- **Source:** `pstack/skills/technical-writing`
- **Summary:** Disciplined authoring of RFCs, technical specs, data dictionaries, and architectural proposals.
- **Rules:** Focuses on concrete trade-offs, constraints, and data definitions rather than promotional marketing language.

## 2. Investigation & Codebase Comprehension

### `how` & `why`
- **Source:** `pstack/skills/how`, `pstack/skills/why`
- **Summary:** Read-only exploration playbooks.
- **Rules:** 
  - `how`: Traces runtime data flows, subsystem ownership, and module boundaries to build a senior-engineer mental model without modifying code.
  - `why`: Investigates git history, commit contexts, and architectural motivation behind existing design choices.
- **Target Stack:** Complex codebases, onboarding to unfamiliar repositories.

### `blast-radius`
- **Source:** `pstack/skills/blast-radius`
- **Summary:** Pre-modification impact analysis.
- **Rules:** Scans imports, call sites, data consumers, and tests to calculate exact downstream dependencies before changing a core signature or schema.
- **Target Stack:** Data Science pipelines (evaluating impact of preprocessing/feature changes across multiple models or training scripts).

### `recall` & `reflect`
- **Source:** `pstack/skills/recall`, `pstack/skills/reflect`
- **Summary:** Post-task evaluation and lesson extraction.
- **Rules:** Analyzes what went wrong in a session or what patterns repeated, extracting reusable rules into local guidelines.

## 3. Testing, Verification & Decision Logging

### `tdd` (Test-Driven Development)
- **Source:** `pstack/skills/tdd`
- **Summary:** Strict Red-Green-Refactor loop.
- **Rules:** Writes the failing test first (`pytest`), implements the minimal code to turn the test green, and verifies before refactoring.
- **Target Stack:** Python libraries, ETL pipelines, and API services.

### `show-me-your-work`
- **Source:** `pstack/skills/show-me-your-work`
- **Summary:** Append-only TSV decision trail for long-running or autonomous tasks.
- **Rules:** Logs `ts`, `phase`, `decision`, `why`, `evidence`, and `result` in a single tabular file (`.tsv`).
- **Target Stack:** Long data science experiments, autonomous sweeps, and parameter tuning.

## 4. Multi-Model Exploration & Stress Testing

### `arena`
- **Source:** `pstack/skills/arena`
- **Summary:** Generates 2–3 competing prototypes for a novel problem and compares their ergonomics, memory footprint, or execution speed.
- **Target Stack:** Benchmarking algorithms, selecting data structures, or evaluating pipeline architectures.

### `swarm`
- **Source:** `pstack/skills/swarm`
- **Summary:** Partitioned exploration sweeps where parallel agents tackle distinct slices of a large search space or matrix.
- **Target Stack:** Hyperparameter sweeps, comprehensive test coverage matrices.

### `interrogate`
- **Source:** `pstack/skills/interrogate`
- **Summary:** Adversarial design review. Questions core assumptions and looks for failure modes before writing code.
